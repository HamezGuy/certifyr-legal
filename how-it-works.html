How Certifyr works

A camera that keeps a record, and a checker anyone can use.

The steps

  1. Capture

    The original is saved on the iPhone exactly as the camera produced it, including the iPhone’s normal photo processing. Certifyr doesn’t edit, filter or re-encode it.

  2. Record

    Within minutes, the app sends a small signed record — the file’s fingerprint, the time and the device model, not the photo. Apple’s App Attest lets Certifyr check that it came from the real Certifyr app. Shots taken while signed out or offline are saved, but never get a record later.

  3. Upload

    If the owner uploads the original, Certifyr registers it only when its bytes match the earlier record exactly, then signs a receipt listing what it checked.

  4. Check

    Once the original is uploaded, anyone can check it. Changing even one byte — by editing, resizing or taking a screenshot — makes it a different file, so only the exact file matches, or a copy Certifyr itself made from it.

  5. Search

    If a photo doesn’t match, Search for Copies sends it to Certifyr, which looks for the invisible watermark in copies Certifyr made, then compares the picture itself with registered photos — Certifyr’s own, not the whole web. A copy it finds is only ever called a copy, never the original. The photo is deleted after the search.

What a result shows

Each result answers three separate questions.

Origin What supports this file’s origin?

  • Taken with Certifyr

    App-attested capture. Doesn’t prove what the scene shows.

  • Taken with Certifyr (test build)

    Made with a development build.

  • Test only

    Created during testing — not real evidence.

  • Registered

    Added after it was taken, so its origin is unknown.

  • Still checking

    Certifyr hasn’t finished checking the record yet.

  • Couldn’t be confirmed

    The record didn’t pass Certifyr’s checks — that doesn’t make the file fake.

  • No longer valid

    The record was valid, but it has since been withdrawn.

  • Not available right now

    Certifyr couldn’t check this record.

  • No Certifyr record

    This file has no Certifyr record of its own — not a sign that it’s fake.

Match How does your file match?

  • Exact match

    This is the same file.

  • Matches a copy

    Not the original file.

  • Copy of a Certifyr photo

    A compressed or edited copy — not the original file.

  • No matching public record found.

    This does not establish whether the image is genuine.

  • Couldn’t compare

    The check didn’t finish, so there’s no answer yet.

Original Can you inspect the original?

  • Original available

    You can open the original file.

  • Original is private

    The original is stored, but its owner hasn’t shared it.

  • Original not uploaded

    The owner hasn’t uploaded the original.

  • Original no longer hosted

    The original was online for a limited time, which has ended.

What a result can’t tell you

Certifyr doesn’t detect fakes. It checks for a matching record made by its camera app, and a result doesn’t prove:

  • That the scene is real, unstaged, or shows what it seems to show.
  • Who took the photo or video, or who owns it.
  • When or where it was taken. Capture times come from the device’s own clock, and Certifyr never asks for your location.
  • That a file without a record is fake, generated, or edited. Most genuine photos and videos are never registered.
  • That a copy is unchanged. Search for Copies can find a compressed or edited copy of a registered photo, but only the exact original file carries its record.
  • That a picture of a screen shows a real scene. A photo of a screen is still a photo taken by the camera.

Your photo stays on your device.

When you check a file, your browser computes its fingerprint — a SHA-256 value, a short code that changes completely if even one byte of the file changes — and sends only that. A check never uploads the file. The one exception is Search for Copies, and only when you tap it: the photo is analyzed to find copies, then deleted. Privacy Policy

Verify It Yourself

A share link can include an evidence bundle, so anyone can check a capture without Certifyr.

  1. On the share page, open Technical Details and download the evidence bundle.
  2. Download the Verifier — a single file for Node.js 20 or later.
  3. Run it with the bundle and your copy of the file:node verify-evidence-bundle.mjs bundle.json photo.jpg

It checks Apple’s certificate chain, the signed capture record, your file and Certifyr’s receipt against the public keys. The strongest result it reports is “App-attested capture”. A receipt is a service receipt, not a certificate.

Good to know

  • Records made with development or test builds are clearly marked and shouldn’t be relied on.
  • Certifyr isn’t affiliated with or endorsed by Apple. App Attest is an Apple service used to check the app’s integrity.
  • The invisible watermark is Adobe’s open-source TrustMark, added by Certifyr to the copies it makes — not an Apple feature. It holds only a random code, and a watermark alone never counts as a match: the picture must also look like the registered photo.
  • “Shared by” shows a name and links the owner chose to add. Certifyr doesn’t confirm who they are.
  • Two photos of the same subject from the same spot — the Moon, a landmark, burst shots — can look like copies of each other. A found copy always comes with the registered photo, so you can compare.
  • Every registration goes into a public log whose checkpoints are timestamped in Bitcoin, so no one — Certifyr included — can quietly change, remove or backdate a record. If an iPhone is caught faking photos, everything it registered is marked “No longer valid”.
